\begin{abstract}
This report presents the complete progress on the food pantry item classification and nutritional matching pipeline. Task~1 classifies pantry images into 21 food categories using Florence-2, achieving 80.3\% micro F1 through an ensemble of generative and contrastive classifiers. Task~2 matches classified items to the USDA FoodData Central database for automatic nutritional estimation. We evaluate multiple approaches including fine-tuned classification, supervised contrastive learning, detection-first pipelines, OCR-based input signals, VLM chain-of-thought reasoning, and ensemble methods. The full end-to-end pipeline is evaluated with error propagation analysis showing moderate nutritional overestimation under misclassification.
\end{abstract}

\section{Task 1: Pantry Item Classification}
\label{sec:task1}

\subsection{Problem Definition and Dataset}

Task 1 classifies food pantry images into 21 predefined categories. The dataset contains 1,123 images split approximately 70/15/15 for training, validation, and testing (166 test images with 1,932 object-level annotations). Approximately 34\% of images contain more than one category (average 1.55 categories per image), making this a multi-label classification problem.

The dataset is imbalanced: the largest class has 189 images while Baby Food has 11 and Vegetables -- Fresh has 21. Some classes (e.g., Carbohydrate Meal and Ready Meals) are visually similar and frequently co-occur, increasing difficulty.

\subsection{Model and Training}

\textbf{Base model:} Florence-2-large-ft \cite{xiao2023florence2}, a unified vision--language model supporting multiple vision tasks through structured text output.

\textbf{Adaptation:} LoRA fine-tuning on both the vision encoder and language decoder, with class-balanced oversampling (\texttt{min\_samples\_per\_class}), confusion-pair boosting for weak classes, and focal loss with label smoothing.

\textbf{External data:} We mapped part of the Grocery Store Dataset \cite{klasson2019grocery} into the pantry taxonomy and used matched classes as additional training data.

\subsection{Training Version History}

Each training version represents a specific configuration change. Understanding this progression is important for interpreting the results:

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Vanilla (zero-shot):} Florence-2 used out-of-the-box with its \texttt{<OD>} (object detection) task. No fine-tuning. The model detects generic objects but has no knowledge of pantry categories. This serves as the lower-bound baseline.
  
  \item \textbf{v6 (vision+decoder LoRA):} First successful fine-tuning. We applied Low-Rank Adaptation (LoRA) to \textit{both} the vision encoder and language decoder of Florence-2. Previous versions (v1--v5) only adapted the language decoder, which was insufficient. The key insight was that the vision encoder also needs adaptation to learn pantry-specific visual features. Training used the pantry training set only.
  
  \item \textbf{v9 (mixed-data fine-tuning):} Added external training data from the Grocery Store Dataset. We mapped grocery categories to our 21 pantry categories (e.g., grocery ``Pasta'' $\rightarrow$ pantry ``Carbohydrate Meal'') and trained on the combined dataset. Also introduced focal loss (gamma=1.0) with label smoothing (0.1) to handle class imbalance, and confusion-pair boosting: images from frequently confused class pairs (e.g., Ready Meals vs.\ Carbohydrate Meal) were oversampled during training.
  
  \item \textbf{v11 (continued fine-tuning):} Instead of training from scratch, we loaded the best v9 checkpoint and continued training with a lower learning rate ($1 \times 10^{-5}$ vs.\ $5 \times 10^{-5}$). This ``warm restart'' approach preserves learned features while refining decision boundaries. We also increased \texttt{min\_samples\_per\_class} to ensure every category appears at least 15 times per epoch, and added targeted boosting for the 5 weakest classes (Dairy, Vegetables Fresh, Nut Butters, Granola, Ready Meals). \textbf{This became the best single generative model at 76.5\% micro F1.}
\end{itemize}

\section{Task 1: Extended Experiments}
\label{sec:task1_extended}

Following the initial fine-tuning results, we conducted several additional experiments exploring alternative approaches suggested in the literature and by collaborators.

\subsection{Detection-First Pipeline}

\textbf{Motivation.} Since under-detection in multi-label images is the main bottleneck, we hypothesized that first detecting individual objects (bounding boxes) and then classifying each cropped object might improve recall. This decomposes the multi-label problem into multiple single-label problems.

\textbf{Method.} We tested three variants:
\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Vanilla OD $\rightarrow$ v11:} Use Florence-2's built-in object detection (\texttt{<OD>} task) to find bounding boxes, crop each detection with 15\% padding, then classify each crop with v11.
  \item \textbf{Fine-tuned OD (labels only):} Fine-tune Florence-2 on the \texttt{<OD>} task using COCO-format bounding box annotations from the training set (10,004 annotations, 15 epochs). Use the OD model's predicted labels directly as classification output.
  \item \textbf{Fine-tuned OD $\rightarrow$ crop $\rightarrow$ v11:} Use the fine-tuned OD model for localization only (ignoring its unreliable labels), crop each detection, classify with v11, and merge with full-image classification as fallback.
\end{enumerate}

\textbf{Results.}

The detection stage dramatically improves recall (70.5\% $\rightarrow$ 87.2\%), confirming that the OD model finds items that v11 misses. However, precision drops from 83.5\% to 41.7\% because v11 was trained on full pantry shelf images and over-predicts on small crops. The OD labels-only approach suffered from label hallucination (7 of 21 categories at 0\% F1).

\textbf{Key insight:} Detection improves recall but the classifier is not trained for single-item crops, destroying precision.

\subsection{OCR-Based Input Signal}

\textbf{Motivation.} Food packaging contains highly discriminative text (brand names, product descriptions, ingredients) that image-only classification may miss. For example, a can of ``Campbell's Chicken Noodle Soup'' is much easier to classify from its label text than from its visual appearance (a generic cylindrical can).

\textbf{Method.} We used Florence-2's \texttt{<REGION\_TO\_OCR>} capability to extract text from detected regions, then matched extracted text against a keyword dictionary mapping common food terms to categories. Two variants:
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{v2 (aggressive):} Broad keyword matching. Any single keyword match boosts the corresponding category. Result: \textit{decreased} F1 from 57.6\% to 48.4\% because nutrition label text (``Calories'', ``Protein''), legal text, and barcodes triggered false matches.
  \item \textbf{v3 (conservative):} Added a blacklist for nutrition/legal text, required multi-word keywords, and required $\geq$2 keyword matches per category. Improved 3 categories (Granola +50\% F1, Savory Snacks +9.4\%, Soup +6.8\%) with minimal impact on others. Overall gain: $\sim$+2\% micro F1.
\end{itemize}

\textbf{Conclusion.} OCR provides modest gains for select categories but is not a reliable general strategy. The difficulty lies in distinguishing informative package text from noise.

\subsection{Supervised Contrastive Learning}
\label{sec:contrastive}

\textbf{Motivation.} The generative approach (v11) produces structured JSON text as output, which means the model must simultaneously understand the image \textit{and} generate valid text. This conflation of classification with text generation may limit accuracy. We investigated a purely discriminative approach that separates feature learning from classification.

\textbf{Architecture.} We keep the entire Florence-2-large encoder (204M parameters) \textbf{frozen} as a fixed feature extractor. On top of the 1024-dimensional encoder output, we add two small trainable heads:
\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Projection head} (2 layers: 1024 $\rightarrow$ 512 $\rightarrow$ 256 with ReLU + BatchNorm): maps encoder features into a normalized embedding space. Trained with Supervised Contrastive Loss (SupCon) \cite{khosla2020supcon}, which pulls images of the same category closer together in embedding space while pushing different categories apart.
  \item \textbf{Classification head} (2 layers: 1024 $\rightarrow$ 512 $\rightarrow$ 21 with ReLU + Dropout): a standard multi-label classifier trained with binary cross-entropy (BCE) loss.
\end{enumerate}

\textbf{Loss function.} The combined loss is:
\[
\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{SupCon}} + (1 - \alpha) \cdot \mathcal{L}_{\text{BCE}}
\]
We set $\alpha = 0.3$ (not 0.5) because the SupCon loss magnitude ($\sim$1.4) is much larger than BCE ($\sim$0.05); $\alpha = 0.3$ ensures both losses contribute proportionally.

\textbf{Why this works.} The key insight is that the pre-trained Florence-2 encoder already produces excellent visual features from ImageNet-scale pre-training. Rather than fine-tuning the entire 204M-parameter model (risking overfitting on 166 images), we train only 1.7M parameters in the two heads. The contrastive loss further structures the feature space by category similarity, while the BCE head performs the actual classification.

\textbf{Variants tested:}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{v1} ($\alpha$=0.5, temperature $\tau$=0.07, lr=$1 \times 10^{-3}$): initial attempt with equal loss weighting.
  \item \textbf{v2a} ($\alpha$=0.3, $\tau$=0.1, lr=$5 \times 10^{-4}$): better-calibrated loss balance, lower learning rate. Slightly higher precision but lower recall.
  \item \textbf{v2b} (same as v2a but \textbf{unfreezing the last 2 encoder layers}): allows the encoder to adapt. \textit{Result:} worse performance (71.9\% vs 77.4\%), confirming that unfreezing causes overfitting on the small dataset.
\end{itemize}

The partially unfrozen variant (v2b) underperforms, likely due to overfitting on the small training set.

\subsection{Ensemble: Generative $\cup$ Contrastive}

\textbf{Motivation.} The generative (v11) and contrastive classifiers make \textit{different types of errors}. v11 is strong on categories with distinctive text descriptions (e.g., Soup, Condiments) but weak on Ready Meals and Savory Snacks. The contrastive classifier excels on visually distinctive categories (Ready Meals: 84.8\% vs v11's 48.0\%) but is weaker on text-dependent ones. This complementarity suggests that combining both could capture items that either model alone misses.

\textbf{Method.} For each test image, we run both models independently and combine their predictions:
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{Union ($\cup$):} A category is predicted if \textit{either} model predicts it. This maximizes recall --- if either model detects an item, it is included. The cost is lower precision (false positives from either model accumulate).
  \item \textbf{Intersection ($\cap$):} A category is predicted only if \textit{both} models agree. This maximizes precision but reduces recall, since both models must independently detect each item.
\end{itemize}

\textbf{Why union works best.} The main bottleneck in Task 1 is \textit{under-detection} (missing items), not false positives. Union directly addresses this by letting each model cover the other's blind spots. The precision cost (77.2\% vs 82.2\%) is acceptable because the recall gain (83.7\% vs 70.1\%) is much larger.

\subsection{VLM Chain-of-Thought Baseline}

\textbf{Motivation.} Recent large vision--language models (VLMs) like GPT-4V and Qwen2.5-VL can perform complex visual reasoning without any task-specific training. We evaluate whether such a model can classify pantry items zero-shot, providing context for the value of our fine-tuning approach.

\textbf{Model.} Qwen2.5-VL-7B-Instruct \cite{qwen2vl}, a 7-billion parameter open-source VLM with instruction-following capabilities. Unlike Florence-2 (0.7B), this model has much more world knowledge from large-scale pre-training.

\textbf{Chain-of-thought prompting.} Instead of simply asking ``classify this image,'' we use a structured prompt that guides the model through explicit reasoning steps:
\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Read} all text, labels, and brand names visible on packaging
  \item \textbf{Identify} each distinct food item in the image
  \item \textbf{Classify} each item into exactly one of the 21 predefined categories
  \item \textbf{Output} a structured JSON response
\end{enumerate}
The prompt includes the complete list of 21 valid categories, two few-shot examples demonstrating multi-label classification, and disambiguation rules for confusable categories (e.g., ``pasta = Carbohydrate Meal'' vs ``canned ravioli = Ready Meals''). No training data is used --- the model relies entirely on its pre-trained knowledge.

\textbf{Technical details.} Images were processed at reduced resolution (max $256 \times 28^2 \approx 200$K pixels, vs.\ default 1M) to fit within A100 40GB GPU memory. We used SDPA attention in bf16 precision. Each image takes approximately 4.7 seconds to process.

The VLM achieves 63.6\% micro F1 zero-shot --- more than double the vanilla Florence-2 baseline. Its recall (70.1\%) matches the fine-tuned v11, demonstrating strong language understanding. The gap is primarily in precision (58.3\% vs 82.2\%), as the VLM occasionally hallucinates categories. The VLM excels on categories with distinctive packaging (Fresh Fruit: 87.5\%, Savory Snacks: 77.8\%) and struggles with visually similar goods (Vegetables Fresh: 28.6\%, Seafood Canned: 40.0\%).

This result demonstrates that while general-purpose VLMs show strong zero-shot capability, fine-tuning on even 166 domain-specific images closes a 17\% F1 gap, justifying the fine-tuning approach.

\section{Task 2: USDA Nutritional Matching}
\label{sec:task2}

\subsection{Overview}

Task 2 matches classified pantry items to the USDA FoodData Central database for automatic nutritional estimation. The full pipeline: image $\rightarrow$ classification (Task 1) $\rightarrow$ USDA matching $\rightarrow$ nutritional output.

\subsection{USDA Data and Index}

\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{USDA Branded Foods:} 454,126 products with brand, description, ingredients, and nutrition.
  \item \textbf{USDA SR Legacy:} 7,793 generic food items as fallback.
  \item \textbf{Embedding model:} all-MiniLM-L6-v2 (384-dim, cosine similarity).
  \item \textbf{Total index:} 461,919 items, 338\,MB embedding matrix.
\end{itemize}

\subsection{Matching Approach}

\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Semantic search:} Each predicted category is encoded and matched against USDA entries by cosine similarity.
  \item \textbf{Category boosting:} USDA items whose \texttt{brandedFoodCategory} relates to the predicted category receive +0.15 score boost.
  \item \textbf{Top-$k$ retrieval:} Top-5 matches returned; top-1 used for nutritional estimation.
\end{enumerate}

\subsection{Limitations}

\begin{itemize}[nosep,leftmargin=1.5em]
  \item Category-level matching is coarse --- USDA match represents an average over items within the category.
  \item No ground-truth USDA mapping exists; quality is assessed via proxy measures.
  \item Classification errors propagate, but impact is moderate at aggregate level.
  \item Brute-force cosine similarity over 461K items; approximate nearest-neighbor (FAISS) could improve speed.
\end{itemize}

\section{Conclusion and Future Work}

\subsection{Summary of Contributions}

\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Task 1:} Developed a pantry item classification pipeline achieving 80.3\% micro F1 through an ensemble of fine-tuned generative (Florence-2) and discriminative (contrastive) classifiers, trained on only 166 images.
  \item \textbf{Task 2:} Built an end-to-end USDA nutritional matching pipeline with semantic retrieval, category boosting, and error propagation analysis.
  \item \textbf{Comprehensive ablation:} Evaluated 10+ approaches including detection-first, OCR, contrastive learning, ensemble methods, and VLM chain-of-thought, providing clear evidence for design choices.
  \item \textbf{Error propagation analysis:} Demonstrated that classification errors cause moderate nutritional overestimation, with the ensemble's higher recall being preferable for food assistance applications.
\end{enumerate}

\subsection{Future Work}

\begin{enumerate}[nosep,leftmargin=1.5em]
  \item \textbf{Fine-grained USDA matching:} Move from category-level to product-level matching using OCR-extracted brand/product names.
  \item \textbf{VLM fine-tuning:} Fine-tune a smaller VLM (e.g., Qwen2.5-VL-3B) on pantry data, potentially surpassing the current ensemble.
  \item \textbf{Active learning:} Use model uncertainty to prioritize annotation of the most informative images.
  \item \textbf{Deployment:} Optimize pipeline for real-time use with FAISS indexing and model quantization.
\end{enumerate}
